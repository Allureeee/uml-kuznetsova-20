# ADR-0003. Для передачи внутренних событий используется очередь RabbitMQ

**Дата:** 2026-10-04  
**Статус:** принято

## Контекст

Архитектура службы такси содержит очередь событий «RabbitMQ». Основной сервис заказов и поездок публикует события, а другие части системы могут получать их через очередь. Одновременно основные запросы между приложениями и сервисами выполняются синхронно через HTTP/HTTPS. Необходимо определить способ передачи внутренних событий системы.

## Рассмотренные варианты

1. Передавать все внутренние сообщения только синхронными HTTP-запросами.
2. Использовать очередь событий для публикации и доставки внутренних событий,
   сохранив синхронные HTTP-вызовы для запросов, где нужен непосредственный ответ.

## Решение

Выбран вариант 2: очередь событий используется для внутренних событий,
а синхронные HTTP-вызовы применяются там, где результат нужен сразу.

## Почему отвергнут другой вариант

Использование только синхронных HTTP-вызовов связывает отправителя и получателя непосредственным ожиданием ответа. Для событий, которые не требуют немедленного ответа, очередь позволяет отделить публикацию события от его дальнейшей обработки. При этом полностью отказываться от HTTP нецелесообразно, поскольку запросы между клиентскими приложениями и Backend API требуют непосредственного результата.

## Последствия

**Плюсы:** разделение отправителя и получателя событий; возможность отдельной обработки событий; сохранение синхронного взаимодействия там, где оно действительно необходимо.

**Минусы:** появляется дополнительный инфраструктурный компонент; необходимо контролировать доставку и обработку сообщений в очереди.
